Q5: What input capabilities should the chat have?

Beyond basic text — what can users send?

A

Rich Text Input

Auto-expanding textarea, markdown support, Shift+Enter for newlines, Enter to send. Code block insertion button. Basic but solid.

B

+ File/Image Attachments

Drag-and-drop or click to attach files. Preview thumbnails before sending. Support images, PDFs, text files. Files stored as base64 in localStorage.

C

+ Voice Input

Microphone button for speech-to-text using Web Speech API. Real-time transcription in the input field. Press and hold or toggle mode.

D

+ Quick Templates / Slash Commands

Type "/" to see command palette: /summarize, /explain, /quiz, /translate. Pre-built prompts for common educational tasks. Customizable template library.

E

+ Context Attachment from Library

"@" to reference saved content from your Content Library. Pulls the content into the conversation context. "Hey, look at @Lecture-Physics-101 and simplify it."

Q6: How should AI responses stream and render?

The response display experience

A

Simple Token Stream

Words appear one by one as they stream in. Markdown rendered after completion. Clean typing indicator (three dots) while waiting. Minimal and fast.

B

Live Markdown Rendering

Markdown renders in real-time as tokens stream. Code blocks get syntax highlighting mid-stream. Headers, lists, bold text all render live. Like ChatGPT.

C

Live Render + Thinking Display

Everything in B, PLUS a collapsible "thinking" section showing the model's chain-of-thought reasoning before the answer. Like your existing generation page's thinking box.
